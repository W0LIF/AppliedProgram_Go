## Авторизация

Все операции с пользователями требуют токен. Токен выдаётся при регистрации
или логине и передаётся в заголовке `Authorization: Bearer <token>`.

Токены живут в памяти сервера: при перезапуске сервера все клиенты должны
войти заново.

### `POST /auth/register`

Создать пользователя и сразу получить токен.

**Тело запроса**

```json
{ "name": "Alice", "email": "a@x.com", "age": 25, "password": "secret1" }
```

**Ответ 201**

```json
{
  "token": "8b1f...e21c",
  "user": { "id": 1, "name": "Alice", "email": "a@x.com", "age": 25 }
}
```

**Ошибки**

- `400` — невалидные поля (см. `details`), в том числе `password` короче 6 символов
- `400` — email уже зарегистрирован

### `POST /auth/login`

Вход по email и паролю.

**Тело**

```json
{ "email": "a@x.com", "password": "secret1" }
```

**Ответ 200** — такой же, как у `register`.

**Ошибки**

- `401` — неверные email или пароль (сервер не различает случаи)

### `POST /auth/logout`

Инвалидирует текущий токен.

**Ответ 204** — тело пустое.

## Клиентское приложение

Исходники — `cmd/client/`. Запуск:

```bash
go run ./cmd/client
```

Адрес сервера берётся из переменной окружения `API_URL` (по умолчанию `http://localhost:8080`):

```bash
API_URL=http://192.168.1.10:8080 go run ./cmd/client
```

### Меню

```
1. Список пользователей
2. Пользователь по ID
3. Создать пользователя
4. Обновить пользователя
5. Удалить пользователя
6. Войти
7. Зарегистрироваться
8. Выйти
0. Выход из программы
```

Токен сохраняется в файл `.lab9-token` в текущем каталоге и автоматически
подхватывается при следующем запуске.

### Формат ошибок в клиенте

Клиент разбирает JSON-ответ и печатает:

```
❌ Ошибка [400]: validation failed
   • email: email is invalid
   • name: name is required
```

### Проверка многопользовательского режима

1. Запустить сервер.
2. Открыть два терминала, в каждом выполнить `go run ./cmd/client`.
3. В каждом терминале залогиниться под своим пользователем.
4. Действия одного клиента (создание, обновление, удаление) сразу
   отражаются в списке у другого.

Сервер не хранит состояние сессии в HTTP — все токены независимы, поэтому
клиенты не мешают друг другу.
